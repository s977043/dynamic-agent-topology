# Support

DAT is an experimental specification and evaluation repository. Support works best when the request is routed by type.

## Usage and adoption questions

Use the repository **Usage or adoption question** Issue form when you have a reproducible question about:

- adopting DAT in a repository;
- schema or validator behavior;
- topology, role, policy, or adapter semantics;
- experiment tooling or examples.

Include the smallest reproducible context you can share publicly.

## Bug reports

Use the repository bug-report Issue form.

A useful report includes:

- DAT commit or version;
- affected file or command;
- expected behavior;
- observed behavior;
- minimal reproduction;
- relevant validation output.

Do not include credentials, private source code, hidden reasoning, or unrelated environment data.

## Research or design proposals

Use the research/design proposal Issue form.

State the source claim or observed problem, the DAT interpretation, the hypothesis, and how the proposal could be evaluated. During an active experiment freeze, proposals may be recorded but implementation can be deferred until the freeze is complete.

## Security issues

Do not publish exploit details or sensitive security information in a public Issue.

Follow `SECURITY.md` for security reporting guidance.
