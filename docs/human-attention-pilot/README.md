# #287 Human Attention — 最初の1ペア実施パケット

**準備用 / 未実測 / 効果未判定。** [Issue #287](https://github.com/s977043/dynamic-agent-topology/issues/287)の任意の手動計測手順を、実際に読める教材と空の記録票へ具体化しました。既存の[計測proposal](https://github.com/s977043/dynamic-agent-topology/blob/40d7b94e027373b659d1860db7e1309535e81d3f/docs/HUMAN_ATTENTION_PILOT.md)が優先します。新しいSchema・必須Gate・Runtimeは作りません。

## 今回決めたこと

| 項目 | 固定する内容 |
|---|---|
| 目的 | 人がactive timeと回答を記録でき、重大な判断材料が両提示に残るかを確認する。効果検定・採用判断ではない |
| Task | PR #289を題材にしたmerge-readiness判断の教材。独立レビュー未到着を仮定する。現在の実PRへの指示ではない |
| 条件 | A=作業順の報告、B=判断項目別。同一の8情報・同一文・同一Evidence・同一5問。分類と順序だけを変える |
| 母集団 | この教材1件、同じ参加者がA/Bを各1回。失敗・中断も記録し、成功するまでの再試行で置換しない |
| 実行 | 同じ端末・viewer・表示設定。人が読むだけ。新たなAgent/モデル/Topologyの実行はN/Aで、AI推論費用を発生させない |
| 測定 | 秒。教材を初めて表示した時点から5回答を固定するまで。実作業、待ち、計測操作を分ける |
| 結果 | 計測可能 / 要修正 / 判定不能。1ペアから時間短縮率や優位性を採用根拠にしない |

AもBも今回編集した教材です。Aを実運用で観測したbaselineや、原文のSoftware Factoryと称しません。比較実装の性能、Runtime強制、AIの自動復旧、モデル費用は今回の検証対象外です。

## 始め方

1. 別の実装非作成セッションへ[QUALITY_REVIEW.md](QUALITY_REVIEW.md)の準備レビュー依頼を渡す。資料欠落・答え漏れ・権限逸脱があれば修正し、新しい版を固定する。教材の品質確認とPRのmerge承認を区別する。
2. Operatorは[RECORD.md](RECORD.md)を**Git外の非公開場所**へコピーする。下の「開始前の記入」だけを埋める。手順の意味が不明なら開始せず理由を記録する。
3. A/Bを開く前にコイントス等で提示順を決めて記録する。同じparticipant・端末・viewerを使用し、通知を避ける。参加者へは最初の資料と5問だけを渡す。
4. 最初の資料を開いた時に計測を開始。読む・考える・回答を書く時間はactive。外部待ち/離席やtimer・記録操作は別interval。5回答を固定して終了する。解説・正解・他方の回答は見せない。
5. 他方でも同じ操作を行う。前の教材や回答は閉じる。記憶は消せないため、同一教材の再読効果を必ず記録する。片側を中断したらその状態を残す。
6. 両回答を固定してから、別の品質確認担当が[QUALITY_REVIEW.md](QUALITY_REVIEW.md)とEvidenceを使って採点する。作成者の自己点検を独立評価にしない。不在なら品質は`unavailable`のままにする。
7. intervalの和集合を照合し、計測可能性だけを判断する。公開するのは匿名集計・資料revision・制約・次の一手のみ。実回答・個人行動ログは公開Issueへ貼らない。

## 開始前の記入 — 人が決める残り

記録票のpackage revision、実施日、参加への同意、匿名ID、viewer、提示順、既知資料/正解への事前接触、保存場所/削除予定、品質確認担当の参照を記入します。氏名や連絡先は不要です。package revisionはこの5ファイルを含むcommit SHAを指定し、作業中のmainという名前だけでは固定しません。

提示の編集・順序変更・質問の追加は開始後にしません。片側の結果を見て教材を直した場合、そのblockは中断として残し、新しいrevision・blockで別の計測にします。

この教材は公開済みで、既にPR #289や本資料を知っている人も対象になりえます。事前接触ありなら**非盲検の手順リハーサル**です。未接触でも同一人の再読効果は残ります。将来の効果評価には未見の複数task、独立した参照基準、順序の釣り合わせ、試行数・改善幅・欠測規則の事前固定が別途必要です。

## 時間・品質の扱い

`active_seconds = 長さ(union(active intervals))`。coordinationはactiveの内訳で、再加算しません。例として[0,60]と[40,100]なら100秒です。時間の記入を忘れたら推測で埋めず`unavailable`。観測が完全な場合だけ0を使います。Agent待ち・PR経過時間から人の時間を計算しません。

このパケットは`explicit`計測を使います。区間が不明なら一点推定せず、今回は欠測として扱います。active / wait / measurementの重なりや説明できない空白は計測不備として記録します。読み込み待ちを含むwall timeはactiveとは別です。

**計測可能:** 両資料の回答・区間が回収でき、重複/欠測を説明でき、独立した品質確認で両資料の5問がすべて正しく抽出され、重大情報の欠落・権限逸脱がない。

**要修正:** 誤ったmerge許可、重大材料の欠落、教材間の情報差、計測方法の不備を具体的に確認した。人の誤答を資料の欠陥と即断せず原因を分ける。

**判定不能:** 片側未実施/中断、主要時間の欠測、品質確認担当不在などで条件を評価できない。安全違反があれば判定不能だけに隠さず別記する。

いずれもHuman Attention改善の採用判定ではありません。差を記録しても「この1ペアの記述値」に留めます。自己報告の秒数は認知負荷全体の測定ではありません。

## 費用・停止・公開

新規有料API、Agent起動、追加SaaS、repo書込み、実PRの承認/mergeは実施手順にありません。人の所要時間・計測overheadは0とせず、測定対象です。秘密・個人情報の入力が必要になる、資料が取得不能、手順外操作や未承認課金が必要になる場合は停止します。

初期資料はbase `40d7b94e027373b659d1860db7e1309535e81d3f`を参照。PR #289は既にmainへ統合済みで、#286も解決済みです。今回の教材仮定を理由にそれらを再openしたり、実PRの状態を戻したりしません。

**未実施:** 人による時間計測、独立した回答採点、効果評価。準備PRのCI成功はそれらを代替しません。#287はOpenのままです。
