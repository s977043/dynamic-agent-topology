# 準備レビュー・回答採点 — 参加者へは計測後に提示

**候補の採点基準であり、独立レビュー済みではありません。** 作成者の結論を正解とみなさず、固定したEvidenceと教材前提に照合してください。両回答を固定するまで参加者に見せません。公開ファイルなのでアクセス隔離を保証せず、事前に見た場合は非盲検リハーサルと記録します。

## 準備を確認する別セッションへの依頼

```text
Issue #287のHuman Attention計測パケットをread-onlyでレビューしてください。
対象: このPRの最新headにある docs/human-attention-pilot/ の5ファイル。
最初にPR番号、head/base SHA、diff、Issue #287の現在地、AGENTS.mdを読み、参照する版を記録する。
A.md / B.mdの8情報が同じか、各Evidenceリンクの内容が主張を支持するか、未到着レビューという教材仮定が現在のPR状態と区別されているかを確認する。
RECORD.mdに未実測の数値/PASSが入っていないか、時間の重複・欠測・記憶効果・非公開保存が扱われているかを確認する。
下の採点基準をbaseline/candidateとは独立にS1-S4と既存の権限規則へ照合する。誤りがあれば開始前に指摘する。
変更・merge・release・課金・モデル実験を実行しない。自分が同じ材料を作成/修正したセッションなら独立レビューとは記載しない。
返すもの: head/base、読んだ差分、runtime/model/session ID（取得不能ならその旨）、具体的な指摘と根拠、未取得材料、計測準備の可否。PR merge判定をする場合は既存のreview_package書式と権限条件を使用し、計測準備可否とは区別する。
```

既存の`scripts/review_package.py build/prompt/record`を使える環境では、PRと#287を材料にして準備します。同スクリプトはReviewerの起動・投稿を代行しません。GitHub connectorしか使えない環境は、PR diff・対象5ファイル・AGENTS・#287・S1-S4の原文を渡し、取得不能箇所を記録します。新しいreview runnerは追加しません。

## 5問の採点基準（開始前に固定、両条件に共通）

各問は必要要素を満たすと1、不足/誤りは0、採点不能はnull。言い回しや短さでは採点しません。

| 問 | 1とする内容 | 許容しない判断 |
|---|---|---|
| Q1 | 教材時点では条件未充足。独立レビュー未到着を特定 | CI成功だけで今mergeしてよい |
| Q2 | 実装非作成の別セッション担当がhead/diff/Evidenceをレビューし、その後最新head/base/CI等を確認。自己レビューで代替不可 | 作成者が同じセッションで承認、架空のReviewerを立てる |
| Q3 | 片側欠測の平均比変更、曖昧除外exit 2、pairedMetricSummary追加を特定 | すべて後方互換、Schema変更と誤認 |
| Q4 | S2の場所、Python3.12.15、原本33blob維持、active-freezeとmacOS sandboxの未実行、合成mergeはmain mergeでないことを抽出 | SKIPを実行成功扱い、ソースのないPASS |
| Q5 | 実測がないため注意時間改善は未証明。合成/数値非回帰と効果を区別 | テスト成功から人の時間短縮を断定 |

品質は両資料で5/5を確認します。重要情報が片方にない、誤承認につながる場合は時間が短くても採用しません。回答の誤りと、資料自体の可視性欠陥は別々に記録します。独立担当が原文確認した記録がなければ、作成者の5/5を独立した品質Evidenceにしません。

## 混同を検出する負側ケース（実測ではない）

- 「CIが緑なのでmerge可」→ Q1=0、誤承認フラグ。A/Bの秒数が良くても救済しない。
- 時間計測なしで0秒を記入 → unavailableへ戻す。値の推定補完をしない。
- 片側だけcompleted → 両側の差はnull、計測可能性は判定不能。失敗側を削除しない。
- 両側の時間が取得済みでもReviewer不在 → 品質はunavailable、総合は判定不能。
- 既に正解を読んだ参加者 → 事前接触を記録し、非盲検の手順確認に限定する。
- 別途「実PRはmerge済み」と知っている → 教材前提への回答と実GitHub状態を区別する。実PRを戻さない。

## 記録してよい結論

準備の評価は「この版の材料で手順確認へ進めるか」です。実測後の評価は計測可能性までです。準備レビュー、回答採点、PR merge可否、改善の採用判断は別の記録として扱います。
