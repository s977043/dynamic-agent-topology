# 不具合報告: 隣接する文字列リテラルを連結すると文字列の意味が変わる

作業ディレクトリの repository（pycparser）にある次の不具合を修正してください。

## 症状

C では、隣接する文字列リテラル（`"a" "b"`）は、各リテラルのエスケープを解釈した後で連結される。pycparser で解析すると、隣接するリテラルが 1 つの文字列表記にまとめられるが、そのまとめ方によって文字列の意味が変わることがある。

- `"\7" "65"`（文字 `\7`、`6`、`5` の 3 文字）が `"\765"`（1 文字）になる。`"\x4" "b"` も `"\x4b"` になる
- `"a?" "?("` のように、連結すると `??(` などの三文字表記（trigraph）ができる組み合わせが、そのまま 1 つの文字列にまとめられる

解析結果から C のソースを生成し直すと、元のソースと意味の違う文字列が出力される。

## 再現手順

```python
from pycparser import CParser
from pycparser.c_generator import CGenerator

p = CParser()
for src in [r'char *s = "\7" "65";',
            r'char *s = "\x4" "b";',
            r'char *s = "ab" "cd";',
            'char *s = "a?" "?(";',
            'char *s = "??" "/";']:
    ast = p.parse(src)
    print(src, "->", CGenerator().visit(ast).strip())
```

## 期待結果

- 解析結果の文字列（定数の値）と、そこから生成したソースは、元の隣接リテラルと同じ文字の並びを表す。エスケープ（8 進・16 進）や三文字表記の境界が、連結によってずれない
- 連結しても意味が変わらない入力では、解析結果と生成結果はこれまでの動作を保つ
- 先頭のエンコーディング接頭辞（`L`、`u8`、`u`、`U`）があっても同じように扱われ、生成したソースを再び解析すると同じ結果になる

## 実際の結果

```text
char *s = "\7" "65"; -> char *s = "\765";
char *s = "\x4" "b"; -> char *s = "\x4b";
char *s = "ab" "cd"; -> char *s = "abcd";
char *s = "a?" "?("; -> char *s = "a??(";
char *s = "??" "/"; -> char *s = "??/";
```

エスケープや三文字表記をまたぐ連結で、元とは意味の違う文字列が出力される。
