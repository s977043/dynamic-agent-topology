# Code of Conduct

Dynamic Agent Topology is an open technical project. Participation should make technical disagreement easier to evaluate, not harder to discuss.

## Expected behavior

When participating in Issues, Pull Requests, reviews, or other project spaces:

- discuss ideas, evidence, and observable behavior rather than attacking people;
- separate facts, hypotheses, interpretations, and preferences;
- give review feedback that is specific enough to act on;
- acknowledge uncertainty and correct claims when stronger evidence appears;
- respect privacy, confidentiality, and security boundaries;
- avoid harassment, discrimination, threats, intimidation, or deliberately disruptive behavior;
- do not pressure maintainers or contributors to bypass experiment, review, or security controls.

Strong disagreement is acceptable. Personal abuse is not.

## Evidence-oriented discussion

DAT intentionally tests competing approaches. A rejected hypothesis, failed run, or inconclusive result is not a personal failure.

Do not manipulate or selectively omit evidence to win an argument. Do not present partial experiment results as settled project conclusions.

## Scope

This Code of Conduct applies to project-maintained spaces, including repository Issues, Pull Requests, review discussions, and other official project channels.

## Reporting conduct problems

For ordinary moderation concerns, contact the repository maintainer through an appropriate GitHub channel without escalating the dispute publicly.

If a report includes a security vulnerability, credentials, private data, or exploit details, follow `SECURITY.md` and do not post sensitive details in a public Issue.

Maintainers may edit, hide, lock, or remove content and may restrict participation when behavior repeatedly violates these expectations.

## Enforcement principle

Moderation decisions should be proportionate, documented when practical, and focused on protecting productive technical collaboration.
